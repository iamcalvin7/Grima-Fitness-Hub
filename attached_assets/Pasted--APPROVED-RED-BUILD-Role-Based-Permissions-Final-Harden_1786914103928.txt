This gate must prove through real database-backed tests that:

* Clients cannot assign or change roles
* Clients cannot access another Client’s records
* Clients cannot access Marcus routes
* Tenant boundaries cannot be crossed
* Role changes take effect on the next authenticated request

* Provisioning and audit operations are transactionally safe

## Stage 1 — Isolated test-database harness — 20 points

Build an isolated database-backed integration-test harness.

Preferred order:

1. Dedicated `TEST_DATABASE_URL` that is positively identified as non-production and different from `DATABASE_URL`.
2. If unavailable, a uniquely named temporary PostgreSQL schema inside the confirmed Replit development database.

A temporary schema is acceptable only when:

* Its name contains an unmistakable test prefix plus a random run identifier
* The connection search path is restricted to that schema
* Production/deployment indicators fail closed
* Normal development tables cannot be read or written
* All migrations run inside the isolated namespace
* The namespace is removed after the suite, including after test failure
* Cleanup is physically verified

Mandatory safety guards:

* Refuse when `REPLIT_DEPLOYMENT` is set
* Refuse when the target equals a production or deployment database
* Refuse an unscoped/default schema
* Refuse `public`
* Refuse a schema/database name without a test marker
* Never print credentials or complete connection strings
* Never reuse development users or records
* Use deterministic fixtures created only inside the isolated environment

Add tests for the harness safety guards and cleanup behaviour.

Stop if safe isolation cannot be proven.

## Stage 2 — Privilege-escalation and ownership integration tests — 30 points

Using only isolated fixtures, implement real request/database tests proving:

### Signup and identity creation

* Signup ignores or rejects caller-supplied `role`
* Signup ignores or rejects caller-supplied `tenantId`
* New users receive the Client role
* OAuth identity creation cannot assign `admin` or `trainer`
* OAuth profile data cannot override role or tenant

Do not call a live OAuth provider. Exercise the internal callback/user-creation boundary with deterministic fixtures.

### Profile isolation

* Profile update cannot change role
* Profile update cannot change tenant
* Profile read uses the authenticated user ID
* Client A cannot read or update Client B
* Caller-supplied user IDs are ignored or rejected

### Session ownership

* Client A cannot revoke Client B’s session
* Client A can revoke their own permitted session
* Missing authentication is denied
* Unknown sessions fail safely

### Marcus route denial

Prove Client and legacy trainer receive 403 on every currently implemented Marcus-only route group:

* Content administration
* Proposal administration
* Audit reads
* Any additional capability-protected route discovered during inspection

Marcus/admin must retain access.

## Stage 3 — Cross-tenant and role-change tests — 25 points

Create at least two isolated tenants with separate Clients and one Marcus fixture where permitted.

Prove:

* Tenant A cannot read Tenant B content
* Tenant A cannot modify Tenant B content
* Tenant A cannot read Tenant B audit records
* Proposal data remains tenant-scoped where tenant context applies
* Session and profile operations remain tenant-safe
* Upload keys contain only the authenticated user/tenant scope
* Caller-supplied tenant identifiers cannot cross the boundary

### Role-change behaviour

Using an authenticated session fixture:

1. Begin with an admin/Marcus user.
2. Confirm an approved capability request is allowed.
3. Change the isolated fixture’s role to Client directly in the test database.
4. Reuse the same session token.
5. Confirm the next request is denied without requiring a new login.
6. Change the role back to admin.
7. Confirm the next request is allowed.
8. Confirm no role is cached inside the session token.
9. Confirm missing or invalid roles fail closed.

No production session architecture change is expected. If the test exposes cached-role behaviour, stop and report before implementing a fix.
