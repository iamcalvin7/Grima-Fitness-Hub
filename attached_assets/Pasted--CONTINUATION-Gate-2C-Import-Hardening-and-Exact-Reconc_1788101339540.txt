# 2. Importer hardening

Implement the independent-review requirements:

* Use one transaction for the complete import operation.
* Acquire a transaction-scoped advisory lock before conflict evaluation and writes.
* Fail safely if another import holds the lock.
* Recheck conflicts inside the locked transaction.
* Validate the selected actor is:

  * Active
  * An admin
  * In the exact target tenant
  * Authorized for the required exercise-management action
* Reject inactive, cross-tenant, client and legacy-trainer actors.
* Require an explicit development target.
* Fail closed when production, deployment or an ambiguous environment is detected.
* Do not rely on one weak environment flag where established deployment markers or connection safeguards are available.
* Never print credentials, full connection strings or sensitive identifiers.
* Validate the complete expected source-ID set before any write.
* Keep dry-run behavior completely write-free.
* Preserve existing-record conflict protection.
* Preserve audit failure rollback.
* Preserve tenant-safe child mappings.
* Never activate an imported exercise.

Add focused tests for these protections.
