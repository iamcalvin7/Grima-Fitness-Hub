Task #36 — Training Wallet Top-Ups via Stripe Checkout

Objective

Add automatic Training Wallet top-ups using Stripe Checkout in Test Mode.

The client experience should be:

Training Wallet
→ Add Training Value
→ choose amount
→ Stripe Checkout
→ Apple Pay / Google Pay / card where available
→ verified successful payment
→ wallet automatically credited

The existing commercial engine remains unchanged:

Wallet value
→ booking maximum hold
→ class-close price lock
→ attendance/no-show settlement
→ Marcus revenue

A wallet top-up is not session revenue.

8. Critical Wallet Credit Rule

This must be absolute:

Stripe Checkout success redirect
≠
wallet credit

The browser returning to Marcus Fitness is not authoritative proof of payment.

The wallet may only be credited following server-side verified Stripe payment confirmation.

Preferred flow:

Stripe
→ signed webhook
→ Marcus backend
→ verify event
→ verify relevant payment/Checkout state
→ transactionally credit wallet

⸻

9. Webhook

Implement a Stripe webhook endpoint following current Stripe guidance.

The endpoint must:

1. Receive the raw webhook body as required by Stripe signature verification.
2. Verify Stripe-Signature.
3. Reject invalid signatures.
4. Resolve the internal top-up from Stripe identifiers.
5. Verify the top-up belongs to the expected amount/currency/client context.
6. Process relevant successful payment event.
7. Credit the wallet exactly once.
8. Safely handle duplicate webhook delivery.

Do not require client authentication for Stripe’s webhook route.

Stripe authentication is through webhook signature verification.

⸻

11. Transaction Boundary

When authoritative payment success is processed:

BEGIN
top-up → paid
cash-backed ledger movement → +€100
top-up linked to movement
creditedAt set
COMMIT

If wallet credit creation fails:

* do not pretend the top-up is completely credited;
* retain enough state for safe reconciliation/retry;
* never create two credits later.
