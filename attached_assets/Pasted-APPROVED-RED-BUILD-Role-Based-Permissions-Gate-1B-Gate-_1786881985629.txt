Intended impact

Clients must be denied access to Marcus-only APIs and must not be able to render Content Admin by manipulating frontend state.

Marcus is represented technically by role = "admin" and must retain access to approved coaching and administrative capabilities.

The legacy technical role trainer is not an approved v1 product actor and must receive no Marcus capabilities.

Server-side enforcement remains the security authority. Frontend guards are an additional UX safeguard only.

Scope boundaries

This envelope authorises:

1. A read-only legacy-trainer preflight
2. Capability middleware and unit tests
3. One protected-route canary
4. Conditional migration of matching privileged guards
5. A Content Admin page-level Client guard
6. Complete verification and one consolidated report

It does not authorise:

* Schema or migration changes
* User-data mutations
* Creating, promoting, or provisioning Marcus
* Audit-log persistence
* Session architecture changes
* Authentication configuration changes
* Environment-variable changes
* Production database access
* Deployment or publishing
* New production dependencies
* Unrelated refactors or formatting changes
