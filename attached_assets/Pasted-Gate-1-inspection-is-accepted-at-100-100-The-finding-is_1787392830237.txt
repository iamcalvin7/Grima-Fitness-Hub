## Stage 2 — Client booking APIs — 25 points

Build authenticated Client APIs using existing route conventions.

Minimum routes:

* `GET /api/training-sessions`
* `GET /api/training-sessions/:id`
* `GET /api/bookings`
* `GET /api/bookings/:id`
* `POST /api/bookings`
* `POST /api/bookings/:id/cancel`
* `POST /api/bookings/:id/reschedule`

### Session discovery

Clients may see only:

* Their tenant’s active scheduled sessions
* Sessions within validated date boundaries
* Capacity information safe for Client display
* Location and session-type information

Do not expose private Marcus notes or other Clients.

### Booking creation

Require:

* Authenticated Client
* Training-session ID
* Client-generated idempotency key

Server derives:

* Client user ID
* Tenant ID
* Initial status
* Audit actor
* Capacity state

Rules:

* New booking status is `pending`
* Pending and confirmed bookings reserve capacity
* Session must be scheduled and in the future
* Client and session must share a tenant
* Replayed idempotency key returns the original result
* Same Client cannot create two active bookings for one session
* Capacity must never be exceeded

Use a transaction and database locking. Concurrent requests for the final place must produce exactly one success.

### Cancellation

Clients may cancel only their own future `pending` or `confirmed` booking.

Rules:

* No price, credit or penalty logic
* Preserve booking history
* Repeated cancellation is idempotent
* Another Client’s booking is not discoverable
* Past, rejected, attended or no-show bookings cannot be cancelled

### Rescheduling

Rescheduling must be one transaction.

Rules:

* Client owns the original booking
* Original booking is pending or confirmed and in the future
* Replacement session is eligible and has capacity
* Lock affected sessions in a stable order
* Create the replacement booking as pending
* Mark the original booking as rescheduled
* Preserve the relationship between both bookings
* If replacement creation fails, the original booking remains unchanged
* Idempotent retries return the original reschedule result

Audit every successful create, cancel and reschedule.
